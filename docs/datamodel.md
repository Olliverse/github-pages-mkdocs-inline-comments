# Data model

GitHub is the database. One annotation = one GitHub issue ([ADR-004](adr/0004-one-issue-per-annotation.md)) in the configured repository ([ADR-003](adr/0003-issues-as-comment-store.md)), carrying the configured label (default `docs-review`). This page is the binding contract between the **producer** (the widget) and all **consumers** — humans triaging in the GitHub UI, and the fix-loop agent reading via `gh`.

Format version: **`ghc` 1**.

## The record

The issue body has three zones — quote header, prose comment, annotation block:

`````markdown
> 📍 [use-cases](https://olliverse.github.io/github-pages-mkdocs-inline-comments/use-cases/#:~:text=the%20widget%20stays%20fully%20silent) — annotated text:
>
> > the widget stays fully silent by design

This reads like a feature, but it is accepted debt — link QDR-002 here
instead of describing it as intended behavior.

<details>
<summary>annotation data (machine-readable — do not edit)</summary>

```json
{
  "ghc": 1,
  "src": "docs/use-cases.md",
  "page": "use-cases/",
  "selector": {
    "type": "TextQuoteSelector",
    "exact": "the widget stays fully silent by design",
    "prefix": "nothing is fetched on page load — ",
    "suffix": " (QDR-002); opening the panel"
  },
  "client": "mkdocs-inline-comments/0.1.0"
}
```

</details>
`````

| Zone | Content | Owner | Edited by |
|---|---|---|---|
| **1 — Quote header** | Blockquote: pin emoji, link to the rendered page (with a [text fragment](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment/Text_fragments) jumping to the passage), nested quote of the annotated text | Widget | Nobody — regenerated by the widget on every body write |
| **2 — Prose comment** | The reviewer's remark. **Canonical here**: editing the issue body in the GitHub UI is a first-class update path; the annotation block holds no copy | Reviewer | Reviewer — via widget (UC-4) or directly on GitHub |
| **3 — Annotation block** | `<details>` element containing one fenced `json` block: the anchor | Widget | Nobody — never rewritten after creation (UC-4 keeps it untouched) |

The prose zone is everything between the end of zone 1 and the opening `<details>` tag, trimmed. An empty comment is allowed — the quote alone can be the finding.

## Annotation block fields

| Field | Type | Required | Meaning |
|---|---|---|---|
| `ghc` | integer | yes | Format version. This document specifies version `1`. |
| `src` | string | yes | Repo-root-relative path of the markdown source, e.g. `docs/use-cases.md`. What the fix agent opens. Computed at build time (`docs_dir` + `page.file.src_uri`). |
| `page` | string | yes | Site-relative URL of the rendered page (`page.url`), e.g. `use-cases/`. What the widget matches to find the current page's annotations. |
| `selector` | object | yes | [W3C Web Annotation TextQuoteSelector](https://www.w3.org/TR/annotation-model/#text-quote-selector): `type` (always `"TextQuoteSelector"`), `exact` (the annotated text, required), `prefix`/`suffix` (≈32 chars of surrounding context, optional but always written by the widget — they disambiguate repeated phrases). Content-addressed: survives line shifts and edits elsewhere on the page. |
| `client` | string | no | Producer name/version. Informational only — consumers must not branch on it. |

Consumers **must ignore unknown fields** (forward compatibility). Additive optional fields do not bump the version; any breaking change does. A consumer encountering `ghc` greater than what it knows must skip the record and report it, not guess.

As JSON Schema:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["ghc", "src", "page", "selector"],
  "properties": {
    "ghc": { "const": 1 },
    "src": { "type": "string" },
    "page": { "type": "string" },
    "selector": {
      "type": "object",
      "required": ["type", "exact"],
      "properties": {
        "type": { "const": "TextQuoteSelector" },
        "exact": { "type": "string" },
        "prefix": { "type": "string" },
        "suffix": { "type": "string" }
      }
    },
    "client": { "type": "string" }
  }
}
```

## Title

```
review(<scope>): "<quote excerpt>"
```

`<scope>` is `src` relative to the docs dir (typically without the `docs/` prefix) and without the `.md` suffix; the excerpt is `selector.exact`, truncated at a word boundary to ≈50 characters with `…`. The issue list alone then tells you where and what:

```console
$ gh issue list --label docs-review
#12  review(use-cases): "the widget stays fully silent by design"
#11  review(adr/0001-static-pat-auth): "fine-grained PAT in localStorage…"
```

The title is **display-only**. Consumers must never parse it — the annotation block is the contract. The `review` prefix is a producer default and may become configurable; nothing may depend on it.

## Lifecycle

| Annotation state | Issue `state` | Issue `state_reason` | Set by |
|---|---|---|---|
| Open | `open` | — | UC-3 create |
| Resolved | `closed` | `completed` | UC-5, or a `fixes #N` commit landing on the default branch |
| Retracted | `closed` | `not_planned` | UC-6 |

Both the widget and the fix loop only act on `state: open`. `state_reason` distinguishes "addressed" from "withdrawn" after the fact; the REST API cannot hard-delete issues, which is why retraction maps to `not_planned` (see UC-6).

## Reading a record (consumer contract)

1. Select issues by **label** and `state: open`. Never by title.
2. In the body, take the **last `<details>` element whose fenced `json` block parses to an object with a top-level `"ghc"` key**. This is robust against reviewers adding their own code blocks or details elements in the prose zone.
3. Zone 2 (the comment) is the body minus zone 1 (the leading blockquote) and zone 3.

A body without a parsable annotation block is an **invalid record**: the widget ignores the issue entirely; the fix agent may still act on title and prose but should flag the issue rather than silently repair it.

### Anchoring caveat: rendered text ≠ markdown source

`selector.exact` is captured from the **rendered DOM**. The markdown source may spell the same passage differently: inline markup (`**bold**`, `[link](url)`, `` `code` ``), SmartyPants substitutions (`--` → `–`, straight → curly quotes), or HTML entities. Consumers locating the passage in `src` should try a literal match first, then a markup-insensitive/fuzzy match. LLM consumers handle this naturally; mechanical consumers must not assume byte equality.

If the selector no longer matches the rendered page (the passage was edited or removed), the annotation is an **anchor orphan**: still a valid record, shown in the widget's panel but not highlighted (UC-2). If `src` no longer exists at all, the issue lingers — known debt, [QDR-001](qdr/0001-orphaned-annotations.md).

## Recipe for the fix-loop agent

```sh
gh issue list --label docs-review --state open \
  --json number,title,body,author
```

For each issue:

1. Parse the annotation block (rule above).
2. Open `src`, locate `selector.exact` (mind the anchoring caveat), read zone 2 for what to change.
3. Fix the markdown source.
4. Commit referencing the issue — e.g. `docs: clarify silent unauthenticated state (fixes #12)`. Merging to the default branch closes the issue as `completed`; alternatively `gh issue close 12 --reason completed --comment "<what was done>"`.

Skip closed issues entirely; never reopen retracted (`not_planned`) ones.
